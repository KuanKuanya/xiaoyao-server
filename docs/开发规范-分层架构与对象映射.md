# 逍遥游项目开发规范

## 一、分层架构与对象映射规范

### 1.1 设计原则

**关注点分离 (Separation of Concerns)**

不同层次的对象应该只关注各自的职责，避免职责混淆和第三方库注解污染。

### 1.2 对象分层

```
┌─────────────────────────────────────────────────────────────┐
│                        客户端请求                              │
└──────────────────────┬──────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────────┐
│  Action Layer（控制层）                                        │
│  - 接收网络请求                                                │
│  - 使用 Proto 对象通信                                         │
│  - 调用 Mapper 进行转换                                        │
└──────────────────────┬──────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────────┐
│  Proto Objects（协议对象）                                     │
│  - @ProtobufClass 注解                                        │
│  - 只用于网络传输                                              │
│  - 可包含额外的展示字段                                         │
└──────────────────────┬──────────────────────────────────────┘
                       │
                       │  MapStruct Mapper
                       │  （编译时生成，类型安全）
                       ▼
┌─────────────────────────────────────────────────────────────┐
│  Service Layer（业务层）                                       │
│  - 使用 Entity / VO 处理业务逻辑                               │
│  - 不关心网络传输格式                                          │
└──────────────────────┬──────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────────┐
│  Entity / VO（实体对象）                                       │
│  - Entity: @Table 注解，只关注数据库映射                       │
│  - VO: 用于业务层数据组装                                      │
└──────────────────────┬──────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────────┐
│  Database（数据库）                                            │
└─────────────────────────────────────────────────────────────┘
```

### 1.3 对象类型说明

#### Entity - 数据库实体

**职责**：只关注数据库映射

**注解**：
- `@Data` (Lombok)
- `@Table` (MyBatis-Flex)
- `@Id`, `@Column` 等数据库相关注解

**禁止**：
- ❌ 不要添加 `@ProtobufClass`
- ❌ 不要添加 `@ExcelProperty`
- ❌ 不要添加其他第三方库注解

**示例**：
```java
@Data
@Table("t_player")
public class PlayerEntity extends BaseEntity {
    @Id(keyType = KeyType.Auto)
    private Long id;
    private String name;
    private Integer level;
    private Long exp;
    private Integer realmId;
}
```

#### VO - 值对象（Value Object）

**职责**：业务层数据组装，可能包含多个 Entity 的关联数据

**使用场景**：
- 关联查询后的数据组装
- 业务逻辑需要的额外计算字段

**示例**：
```java
@Data
@EqualsAndHashCode(callSuper = true)
public class MapConfigVO extends MapConfigEntity {
    /** 关联的怪物ID列表 */
    private List<Integer> monsterIds;

    /** 关联的掉落物品ID列表 */
    private List<Integer> drops;
}
```

#### Proto - 协议对象

**职责**：专门用于网络传输

**注解**：
- `@Data` (Lombok)
- `@ProtobufClass` (jprotobuf)
- `@Protobuf(order = N)` 标注字段序号

**包路径**：`*.proto` 包下

**命名规范**：`XXXProto`

**示例**：
```java
package com.xiaoyao.logic.config.proto;

@Data
@ProtobufClass
public class MapConfigProto {
    @Protobuf(order = 1)
    private int mapId;

    @Protobuf(order = 2)
    private String name;

    @Protobuf(order = 3)
    private int reqRealmId;

    // 可以包含 Entity 中没有的展示字段
    @Protobuf(order = 11)
    private List<Integer> monsterIds;
}
```

## 二、MapStruct 映射器规范

### 2.1 Mapper 接口

**包路径**：`*.mapper` 包下

**命名规范**：`XXXProtoMapper` 或 `XXXExcelMapper`

**注解**：
```java
@Mapper(componentModel = MappingConstants.ComponentModel.SPRING)
```

### 2.2 基础映射示例

```java
package com.xiaoyao.logic.config.mapper;

import com.xiaoyao.logic.config.dto.MapConfigVO;
import com.xiaoyao.logic.config.proto.MapConfigProto;
import org.mapstruct.Mapper;
import org.mapstruct.Mapping;
import org.mapstruct.MappingConstants;

import java.util.List;

@Mapper(componentModel = MappingConstants.ComponentModel.SPRING)
public interface MapConfigProtoMapper {

    /**
     * 将 MapConfigVO 转换为 MapConfigProto
     */
    @Mapping(source = "id", target = "mapId")  // 字段名不同时需要映射
    MapConfigProto toProto(MapConfigVO vo);

    /**
     * 批量转换
     */
    List<MapConfigProto> toProtoList(List<MapConfigVO> vos);
}
```

### 2.3 复杂映射示例（带额外数据）

```java
@Mapper(componentModel = MappingConstants.ComponentModel.SPRING)
public abstract class PlayerProtoMapper {

    @Autowired
    protected GameConfigService configService;

    /**
     * 转换并附加额外信息
     */
    public PlayerProto toProtoWithRealm(PlayerEntity entity) {
        PlayerProto proto = toProto(entity);

        // 附加境界名称
        String realmName = configService.getRealmName(entity.getRealmId());
        proto.setRealmName(realmName);

        return proto;
    }

    /**
     * 基础映射（由 MapStruct 自动生成）
     */
    @Mapping(source = "id", target = "playerId")
    @Mapping(source = "name", target = "playerName")
    abstract PlayerProto toProto(PlayerEntity entity);
}
```

### 2.4 字段映射规则

#### 同名字段

自动映射，无需声明：
```java
// Entity 和 Proto 都有 name 字段
private String name;  // 自动映射
```

#### 字段名不同

使用 `@Mapping` 注解：
```java
@Mapping(source = "id", target = "playerId")
@Mapping(source = "realmId", target = "realm")
```

#### 忽略字段

```java
@Mapping(target = "realmName", ignore = true)  // 稍后手动设置
```

#### 类型转换

MapStruct 自动处理常见类型转换：
- `Long` ↔ `long`
- `Integer` ↔ `int`
- `Boolean` ↔ `boolean`
- `LocalDateTime` ↔ `String` (需要配置格式)

## 三、Action 层使用规范

### 3.1 标准写法

```java
@Slf4j
@Component
@ActionController(ConfigCmd.cmd)
public class ConfigAction {

    @Resource
    private GameConfigService configService;

    @Resource
    private ConfigProtoMapper configProtoMapper;  // 注入 Mapper

    /**
     * 获取地图配置
     */
    @ActionMethod(ConfigCmd.getMaps)
    public ConfigProto getMaps() {
        // 1. 从 Service 获取 VO/Entity
        List<MapConfigVO> vos = configService.getAllMapConfigVOs();

        // 2. 使用 Mapper 转换为 Proto
        return configProtoMapper.createWithMaps(vos);
    }
}
```

### 3.2 返回值要求

**必须**：
- ✅ Action 方法必须返回 `Proto` 对象
- ✅ 不能直接返回 `Entity` 或 `VO`

**示例**：
```java
// ✅ 正确
public MapConfigProto getMap(int mapId) {
    MapConfigVO vo = configService.getMapConfigVO(mapId);
    return mapConfigProtoMapper.toProto(vo);
}

// ❌ 错误 - 直接返回 VO
public MapConfigVO getMap(int mapId) {
    return configService.getMapConfigVO(mapId);
}
```

```java

    ...
}

// 修改后
@Data
@Table("t_player")
public class PlayerEntity {
    ...
}
```

### 步骤 4：更新 Action 层

```java
// 修改前

    ConfigResp resp = new ConfigResp();
    resp.setMaps(list);
    return resp;

@Resource
private ConfigProtoMapper configProtoMapper;  // 注入

@ActionMethod(ConfigCmd.getMaps)

    List<MapConfigVO> list = configService.getAllMapConfigVOs();
    return configProtoMapper.createWithMaps(list);
}
```

## 五、最佳实践

### 5.1 Proto 对象设计

#### 原则

1. **客户端友好**：字段命名清晰易懂
2. **完整性**：包含客户端需要的所有展示数据
3. **扁平化**：尽量减少嵌套层级

#### 示例

```java
// ✅ 好的设计
@Data
@ProtobufClass
public class PlayerInfoProto {
    @Protobuf(order = 1)
    private long playerId;

    @Protobuf(order = 2)
    private String playerName;

    @Protobuf(order = 3)
    private int level;

    @Protobuf(order = 4)
    private String realmName;  // 展示用，非数据库字段

    @Protobuf(order = 5)
    private long exp;

    @Protobuf(order = 6)
    private long nextLevelExp;  // 计算字段
}

// ❌ 避免复杂嵌套
@ProtobufClass
public class PlayerInfoProto {
    private PlayerEntity player;      // ❌ 不要直接嵌套 Entity
    private RealmEntity realm;        // ❌ 不要直接嵌套 Entity
    private List<ItemEntity> items;   // ❌ 不要直接嵌套 Entity
}
```

### 5.2 Mapper 性能优化

#### 批量转换

优先使用 MapStruct 的批量转换方法：

```java
// ✅ 高效 - 一次转换
List<MapConfigProto> protos = mapper.toProtoList(vos);

// ❌ 低效 - 循环转换
List<MapConfigProto> protos = new ArrayList<>();
for (MapConfigVO vo : vos) {
    protos.add(mapper.toProto(vo));
}
```

#### 缓存 Mapper

Mapper 已自动注册为 Spring Bean，无需每次创建：

```java
// ✅ 注入使用
@Resource
private MapConfigProtoMapper mapper;

// ❌ 不要手动创建
MapConfigProtoMapper mapper = Mappers.getMapper(MapConfigProtoMapper.class);
```

### 5.3 字段顺序管理

Proto 对象的 `@Protobuf(order)` 序号需要持续维护：

```java
@ProtobufClass
public class PlayerProto {
    @Protobuf(order = 1)
    private long playerId;

    @Protobuf(order = 2)
    private String name;

    // 新增字段使用递增序号
    @Protobuf(order = 3)
    private int level;  // 新增
}
```

**注意**：
- 不要删除已有序号
- 新增字段使用新序号
- 保持向后兼容

## 六、常见问题 FAQ

### Q1: 为什么要分离 Entity 和 Proto？

**A**: 关注点分离：
- **Entity** 关注数据库映射
- **Proto** 关注网络传输
- 避免第三方库注解污染
- 不同场景需要不同字段结构

### Q2: MapStruct 和 BeanUtils.copyProperties() 有什么区别？

**A**:
| 特性 | MapStruct | BeanUtils |
|------|-----------|-----------|
| 性能 | 编译时生成，零反射 | 运行时反射 |
| 类型安全 | 编译期检查 | 运行时才发现错误 |
| 字段映射 | 支持复杂映射规则 | 只支持同名同类型 |
| 代码可读性 | 接口定义清晰 | 隐式转换不明确 |

### Q3: 什么时候使用 VO，什么时候直接使用 Entity？

**A**:
- **使用 VO**: 需要关联查询、组装额外数据时
- **使用 Entity**: 单表 CRUD 操作时

### Q4: Proto 对象可以继承 Entity 吗？

**A**:
❌ 不推荐。这会导致：
- Proto 包含不必要的数据库字段
- 破坏了分层架构
- 增加网络传输负担

✅ 使用 MapStruct 映射，保持独立。

### Q5: 如何处理 Proto 中的枚举类型？

**A**:
```java
// Entity 中使用 Integer
public class PlayerEntity {
    private Integer gender;  // 1=男 2=女
}

// Proto 中可以使用 String 或枚举
@ProtobufClass
public class PlayerProto {
    @Protobuf(order = 3)
    private String gender;  // "male" / "female"
}

// Mapper 中转换
@Mapper
public interface PlayerProtoMapper {
    @Mapping(source = "gender", target = "gender", qualifiedByName = "genderToString")
    PlayerProto toProto(PlayerEntity entity);

    @Named("genderToString")
    default String genderToString(Integer gender) {
        return gender == 1 ? "male" : "female";
    }
}
```
